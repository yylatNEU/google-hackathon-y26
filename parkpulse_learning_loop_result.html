End-to-End Loop

1. Live ticketsGuest, employee, dynamic park, place risk, and seeded incidents.
2. Dedupe lifecycleTickets become deduped lifecycle items with review ownership.
3. Learning signalsRepeated tickets and training gaps become product-learning signals.
4. Auto draftLow-risk changes become versioned training or checklist drafts.
5. PromotionSafe versions promote into training/checklist registries only.
6. Runtime useTraining consumes active staff-training versions; backlog consumes ops-checklist versions.
7. OutcomesScores and gaps are measured; regression can auto-rollback.

Built Capabilities

  • Backend-generated live issue tickets from operational backlog, place risk, and random incident rules.
  • Named human review places for safety, accessibility, refund, first aid, security, ride safety, and ops command.
  • Safe auto-learning for low-risk scopes with shadow metrics and rollback guards.
  • Durable version registry with promotion, active, rolled-back, and outcome states.
  • Staff roleplay sessions attach active training versions and record outcome metrics.
  • Operational backlog is augmented by active ops-checklist guidance when a matching version exists.
  • SQLite event store with JSONL compatibility and query indexes.

Guardrails

  • LLM guest simulator never controls score.
  • Training gaps never create live issue tickets.
  • Auto-promotion cannot dispatch, refund, alter safety policy, or mutate live operations.
  • Human review approval applies only to training/checklist learning changes.
  • Rollback only rolls back generated learning versions, not live operations.
